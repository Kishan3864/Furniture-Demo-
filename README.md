# WoodBook — Furniture Workshop Management

*by Brighton Solution*

WoodBook manages a furniture workshop: orders with measurements, workers, stages, deliveries, payments, stock, expenses and reports. It is an installable PWA, mobile-first, and also works on desktop.

**Language:** English is the default. Hinglish is optional, and each device can switch through the language toggle (sidebar, login page or Settings → Language). Translations live in `src/i18n/hi-*.ts`, keyed by the English text that `t()` uses.

**Stack:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Firebase Auth, Firestore and Storage · zod · sonner

---

## 1. Firebase setup (project `furniture-webs`)

1. **Authentication** → Sign-in method → enable **Email/Password**.
2. **Firestore Database** → Create database (production mode, region `asia-south1` recommended).
3. **Storage** → Get started.
4. **Project settings → General → Your apps → Add web app**, then copy the config values into `.env.local`:

```env
NEXT_PUBLIC_FIREBASE_API_KEY=...
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=furniture-webs.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=furniture-webs
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=furniture-webs.firebasestorage.app
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
NEXT_PUBLIC_FIREBASE_APP_ID=...
NEXT_PUBLIC_APP_URL=https://your-domain.com   # used in WhatsApp status links
```

5. Deploy the security rules and indexes:

```bash
npm i -g firebase-tools
firebase login
firebase deploy --only firestore:rules,firestore:indexes,storage
```

`storage.rules` looks up the user's role in Firestore (cross-service rules). The first time you deploy, the CLI asks you to grant Storage access to Firestore. Answer **Yes**.

## 2. Run

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build
npm start
```

## 3. Admin login and roles

Create the admin login once from the CLI. `--demo` and the worker options are optional:

```bash
npm run setup:admin -- --email admin@example.com --password "StrongPass1" --name "Admin" \
  --demo --worker-email worker@example.com --worker-password "StrongPass2"
```

You can also sign in on a fresh project with **Set up admin account**. That link only appears until an admin exists.

- **Admin (owner):** has full access.
- **Worker login:** Admin → Workers → open a worker → **Create login** (email and password). Give those details to the worker.
  - A worker sees only the jobs assigned to them, and can change the stage and upload progress photos.
  - A worker never sees prices, payments or customers. Firestore rules enforce this, because money data lives in the admin-only `finance` and `payments` collections.
- **Changing a password:** Settings → **Change password**.

## 4. Demo data

- **From the app:** Settings → **Load demo data**, or **Remove demo data** to clear it.
- **From the CLI:** `npm run setup:admin -- ... --demo`, or put `SEED_EMAIL` and `SEED_PASSWORD` in `.env.local` and run `npm run seed`.

## 5. Deploy (Firebase Hosting)

**Live:** https://furniture-webs.web.app

The app is a static export (`output: 'export'`) served by Firebase Hosting, so it runs on the free Spark plan.

```bash
npm run deploy        # build + deploy hosting
npm run deploy:all    # build + deploy auth providers, Firestore rules/indexes, hosting
```

**Dynamic routes:** each dynamic route (`/orders/[id]`, `/status/[token]` and the others) is exported once as a placeholder page `_`. The `rewrites` in `firebase.json` send every real id to that placeholder, and the page reads the id from the URL through `useRouteParam()`.

### Photos

- **Default (free plan):** photos are compressed in the browser and stored in the Firestore `images` collection.
- **Switching to Cloud Storage:** Storage on new projects needs the Blaze plan. Once Storage is enabled (Console → Storage → Get started), set `NEXT_PUBLIC_PHOTO_STORE=storage`, run `firebase deploy --only storage`, then `npm run deploy`. Photos already uploaded keep working.

## Install as an app (PWA)

- **Chrome / Edge, desktop or Android:** use the **Install app** button in the sidebar, the top bar, Settings → App, or the login page. The browser's own install icon works too.
- **iPhone:** tap **Install app** to see the steps (Safari → Share → *Add to Home Screen*).
- **Offline:** the service worker precaches the whole app shell. The list is generated by `scripts/postbuild.mjs` on every build, so the installed app opens instantly and works offline.
- **Updates:** each deploy stamps a new version into `sw.js`, and the installed app then shows a toast saying *A new version of WoodBook is ready* with a **Reload** button.

## Guided tour

New users are offered a guided tour after their first sign in. The admin tour has 29 steps covering dashboard, customers, the new-order form step by step, order detail (stages, photos, WhatsApp, payments, bill), work progress board, deliveries, payments, workers, stock, expenses, reports, settings and install. Workers get a shorter tour of their own.

- **Restarting the tour:** use **Take a tour** in the sidebar, the mobile menu or Settings → App.
- **Editing the steps:** steps live in `src/lib/tour-steps.ts` and point at `data-tour="..."` anchors. Hinglish translations are in `src/i18n/hi-tour.ts`.

## Data model (Firestore)

| Collection | Holds |
|---|---|
| `users/{uid}` | role (`owner` / `karigar`), karigarId, active |
| `meta/owner` | one-time owner bootstrap |
| `settings/workshop` | profile, item types, wood types, stages, categories |
| `counters/orders`, `counters/receipts` | auto numbers WB-0001 / RC-0001 |
| `customers` | customer records |
| `orders` | job data, no money (readable by assigned karigars) |
| `finance/{orderId}` | price, discount, paid, balance (owner only) |
| `payments`, `labour`, `stock`, `stockMoves`, `expenses` | owner only |
| `status/{token}` | public read-only mirror for the status page (prices only if enabled per order) |
| `images/{id}` | compressed photos when Firestore photo storage is used |

Records are soft deleted (`deleted: true`) and can be restored from Settings → Trash. Reads still work offline through Firestore's IndexedDB cache, and the service worker caches the app shell and photos.
